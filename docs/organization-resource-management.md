# 组织资源管理验收

打开 `http://127.0.0.1:5173/`，从左下角账号菜单进入「组织管理」，选择目标组织。
管理账号须同时具备「组织管理员」账号角色和目标组织的有效「管理员」或「所有者」成员身份，
可保持开发工程师身份。建议用其他成员拥有的项目、空间验证，避免误把所有者权限当作组织权限。

## 项目管理

项目行「编辑项目」统一修改名称、简介、标签、生命周期、健康度及说明，一次事务保存。
有风险或已失控时必须填写说明；验证失败不得部分保存项目名称。
独立重命名和健康度按钮已合并。成员图标管理项目成员；更多菜单保留所有权转移和删除。
项目转移申请由接收人在项目通知中心确认，72 小时内有效。

项目行的双向箭头用于迁移所属组织，与人员图标的“所有权转移”是两项独立操作。迁移者须同时
是源组织和目标组织的 Owner/Admin，并具备组织管理员账号角色。目标组织必须已包含项目 Owner
和全部有效成员；项目不能有待接受邀请或尚未绑定账号的有效成员；所有曾被待办引用的模块都必须在目标组织存在同名且
启用的目录项。对话框会列出具体阻塞项，全部通过后才允许二次确认。迁移完成后检查旧邀请、
待确认所有权转移和飞书项目群配置已失效，已提交周报快照仍可读取。

项目成员有关联的待处理待办、未交付事件或未结束里程碑时不能移除。组织成员移除还检查未关闭
Bug 和草稿/进行中的测试计划；先完成或重新指派相关工作后再操作，系统不会自动清除负责人。

## 测试空间

上层「测试空间」包含两个子 Tab：

| 子 Tab | 操作 | 预期结果 |
| --- | --- | --- |
| 组织测试空间 | 新建、编辑 | 自动归属当前组织；名称和版本一起编辑，组织内版本号不得重复 |
| 组织测试空间 | 成员管理 | 选择当前组织内具备测试空间资格的成员；未加入者直接加入，已加入者保存只读/可编辑权限或二次确认移除；所有者不可直接修改 |
| 组织测试空间 | 更多 → 所有权转移 | 选择当前组织内具备测试空间资格的成员，二次确认后立即生效；原所有者保留可编辑权限，组织归属不变 |
| 组织测试空间 | 更多 → 删除 | 输入完整空间名称才可删除，空间业务数据随之删除 |
| 测试环境 | 新建、编辑、删除 | 组织统一配置一次，现有和后续新建空间自动共享，无需逐个关联 |

空间行不再单列重命名、调整归属组织。直接添加成员和组织归属 API 保留兼容，
组织管理的成员页面以当前组织有效成员为候选范围。

组织管理中的空间转移不创建申请，也不进入通知中心；确认后立即生效。目标成员须仍具备测试工程师
或组织管理员账号角色。测试工作台中原有的空间转移仍由接收人进入「测试工作台 → 通知中心」确认；
拒绝或过期不改变所有权，接收时若成员资格、原所有者、组织归属、发起人的管理权限发生变化，
应显示明确错误。

测试工作台的空间菜单也提供「管理测试环境」。有组织管理权限的账号可维护，无权限的账号只读。
环境删除影响本组织所有空间；已有 Bug 保留加密的环境快照。删除一个空间不会删除组织环境。

## 权限与并发验证

仅有职业角色、仅有组织管理员成员身份、其他组织成员、已离组账号均不能越权管理。
管理权限不授予测试用例、计划、Bug、数据导入或项目集成配置的额外业务写权限。

运行 `npm run build`、`npm run lint`、`npm test`。明确授权开发 PostgreSQL 后，
运行 `npm run test:resource-management`，配置方式见 [runbook](runbook.md#organization-resource-management-verification)。
该测试使用独立 schema，覆盖原子编辑、共享环境同步与跨组织并发、转移通知隔离、拒绝、过期、
成员移除、管理员失权、接收角色变化、重复确认和最终所有权。

## 项目交付人员

展开项目，在“交付人员”区域点击“配置”。仅同时具备组织管理员账号角色和当前组织 Owner/Admin
成员身份的账号可以配置。列表支持多人，每人分别勾选“计划管理”“交付执行”，允许兼任。
添加人员可搜索姓名或账号；仅当前组织有效、未停用成员可选，尚未加入项目的人员须先通过项目
成员管理加入。“项目负责人”指项目 Owner，与任务的“执行负责人”分别展示。

- 张三仅有计划管理：可以创建、编辑、发布草稿和转交执行人，不能代执行人提交完成。
- 李四仅有交付执行：任务指定给自己后，才能管理执行关联待办/备注和标记已交付。
- 王五兼任：可编制计划；任务指定给自己时才可执行和完成。
- 未配置开发人员、项目 Owner：原有可见范围内只读，不能通过旧接口写入交付记录或反馈。
- 每项任务一位执行负责人，从项目执行名单选择。草稿可暂不指派，发布前必须选择。
- 发布后正文、安装包不再修改。计划人员可填写原因、确认转交；原执行人失去执行权限，保留历史署名。
- 计划人员和当前执行人可写反馈，但只能编辑/删除本人反馈；未配置人员只读。
- 取消执行职责前，先处理该人员负责的未完成任务。成员离组、移出项目或账号停用后旧授权不会在
  重新加入时自动恢复。项目迁移组织会清除名单，须由目标组织重新配置。
- 两位管理员并发编辑，后提交者收到冲突，可“读取最新配置并保留修改”后核对再保存；网络结果
  不确定时只能“核对保存结果”，不会重复提交或因取消/重新打开而解除保护。

验收覆盖直接调用 API、跨事件评论 ID、旧执行人转交后提交、计划人员代完成、发布后正文修改、
普通待办备注接口修改交付来源备注、成员离职并发、管理员冲突保存和窄屏多人配置。
