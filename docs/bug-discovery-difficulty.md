# 缺陷发现难度

发现难度衡量触发并识别缺陷所需的测试条件和观察分析复杂度。仅有高、中、低三级，与严重程度、优先级和修复难度分别记录。

| 等级 | 标准 | 示例 |
| --- | --- | --- |
| 低 | 标准环境、常规数据和正常流程下，基础检查即可发现。 | 标准构建或启动失败、按钮无效、基础流程报错、明显页面问题。 |
| 中 | 需要边界、异常、权限、状态流转或兼容性等专项用例才能发现。 | 边界输入异常、角色权限错误、撤销后重新提交异常、单次断网恢复异常。 |
| 高 | 需要复杂组合、并发时序、长期运行、资源压力或深入观测才能发现。 | 并发数据丢失、特定时序死锁、长期内存泄漏、跨系统隐性数据不一致。 |

按最简单、可靠的发现路径定级。缺陷属于性能、安全或兼容性问题，不直接决定等级；偶发、排查时间长、未自测或漏测，也不能单独作为高难度依据。

新建必须主动选择等级，表单不预选。高等级必须填写评定依据，说明必要触发条件或观察手段，可引用复现步骤；中、低选填。依据最多 1,000 字，非空内容加密保存。历史缺陷统一初始化为中，仅作为兼容初始值，允许报告人校正。

报告人在已有测试空间编辑权限下修改等级与依据；负责人和组织管理者沿用既有读取权限，不因此增加修改权限。两端列表、详情展示发现难度，高级筛选支持等于、不等于。状态和负责人更新不重置评定，空间转移保留评定。

列表两端共用相同布局：编号与状态位于首行，状态使用圆点与文字标签；标题独占一行区域；时间、负责人等辅助信息与发现难度位于底行。发现难度保留文字等级，长标题最多展示两行，长辅助信息允许换行，兼容浅色与深色主题。

## 手工验收

- 新建时只有高、中、低三个选项，未选择无法提交；从失败用例创建也必须主动选择。
- 高等级的空白依据无法提交；填写后可以保存。中、低允许空依据，超过 1,000 字被拒绝。
- 保存后两端列表和详情显示一致，详情按普通文本展示依据；等于、不等于筛选结果正确。
- 编辑预填已有值；修改后保存生效，保存失败保留对话框和输入。省略字段的状态更新不改变评定。
- 非报告人不能通过详情接口修改等级或依据；失去空间编辑权限后不能保存。
- 在获授权的测试数据库中验证：历史记录初始化为中、迁移重跑保留人工修改、数据库拒绝非法等级和空等级、非空依据存储为加密信封。

日常构建、lint 和单元测试不等同于数据库迁移或生产行为验证。迁移与回退要求见 [runbook](runbook.md#bug-discovery-difficulty-migration)。
