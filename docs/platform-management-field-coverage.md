# 平台管理字段覆盖清单

状态：2026-09-18，主体字段迁移与平台页面已在本分支实现；真实数据库和第三方验收状态见 [平台管理实施计划](platform-management-implementation-plan.md)。发生冲突时以当前代码和正式实施计划为准。

## 核对口径

对照 `~/.vage.env` 的键名、`.env.example`、`server/` 实际环境变量读取、`vite.config.ts`、`.sealos/template/index.yaml`、日报 CronJob 模板和 `docs/references.md`。没有输出本机凭据值。以当前代码实际消费为能力依据，模板声明不等于已经实现。

- 本机 env 共 30 项：7 项排除的启动基础配置、22 项实际生效的业务配置、1 项代码未读取的变量。
- 服务端标准业务配置共 34 项，其中 12 项未出现在本机文件。按最新需求分为 28 项可编辑/等价操作、1 项固定只读、2 项隐藏保留、3 项移除输入并保留迁移兼容。
- 另有 5 项旧别名，迁移后合并到标准字段；2 项在本机或模板出现但当前未实现的变量单独列明。
- 下表“本机有”只说明键存在，不代表已填写、凭据有效或外部集成已验证。
- “迁移”保留能力；“补齐”指上一版页面清单未明确列出；“等价替换”说明原 env 名称消失但原配置能力仍可操作。

所有配置具有明确去向：可见项有页面操作，隐藏项保留后台且不被页面保存覆盖，兼容项保留必要迁移和历史读取。普通用户永远不能获得凭据；私有配置不能通过平台信息公共接口泄露。页面优先中文，保留品牌、URL、模型标识、文件名和规则键原文。

包市场规则内容必须保留当前解析能力：`page_kinds` 的 key、label_zh/labelZh、middleware discovery roots，兼容顶层 middleware.roots；每条规则的 ID、name、category、roots、file_name_format/file_name_formats、ci_file_name_formats、dependency_roots、dependency_file_patterns 和 parent。导入使用 YAML 解析器和明确 schema；支持字段不能静默丢弃，未知字段报告后拒绝覆盖。保留已有组织级可见范围/Release/CI 覆盖，不混入全局规则。

## 2. 当前有效的旧别名

| 旧变量 | 归并字段 | 导入行为 |
| --- | --- | --- |
| OSS_UI_DOWNLOAD_EXPIRE_SECONDS | PACKAGE_MARKET_DOWNLOAD_EXPIRE_SECONDS | 保留现有标准变量优先、别名回退的实际解析语义 |
| OSS_UI_MIDDLEWARE_ROOT | PACKAGE_MARKET_MIDDLEWARE_ROOT | 当前代码同时合并两个根目录及内置回退目录；迁移必须保留整个列表，不能简单只取新名 |
| OSS_UI_BASE_OBJECT_TEMPLATE | PACKAGE_MARKET_BASE_OBJECT_TEMPLATE | 保留现有标准变量优先、别名回退的实际解析语义 |
| OSS_UI_BASE_LIST_PREFIX_TEMPLATE | PACKAGE_MARKET_BASE_LIST_PREFIX_TEMPLATE | 同上 |
| TRIAL_COMBO_PACKAGE_RULES_FILE | PACKAGE_MARKET_RULES_FILE | 按现有优先级读取文件并导入规则内容 |

迁移后的界面只有一组标准字段，不展示两套重复选项。旧代码的 `??` 对“未定义”和“空字符串”处理不同，导入应复用或等价实现原解析，不能一律用真假值兜底。规则里的 discovery roots 优先于 env 回退目录，须迁移真实有效配置而非仅复制表面值。

## 3. 已出现但未实现的变量

| 变量 | 出现位置 | 当前实现 | 本次处理 |
| --- | --- | --- | --- |
| FEISHU_DELIVERY_INTERVAL_MS | 本机 ~/.vage.env | 服务端未读取；通知即时投递，私聊 AI 重试定时器另有固定周期 | 迁移报告标为未实现，不作为已生效设置；若接入可调发送间隔属于新增通知调度能力 |
| FEISHU_ENCRYPT_KEY | .env.example、Sealos 模板 | 服务端未读取，尚未实现加密事件解密 | 迁移报告标为未实现，不显示虚假的“加密事件已启用”；若支持它需新增完整飞书加密回调协议 |

这两项不能算作“原有有效功能被删除”，也不能把保存一个字段当成已经支持该功能。迁移不覆盖/删除用户原 env，报告列出名称和处理结果，秘密值不进入报告。

## 4. 新增字段与操作

以下是超出现有 env 的新增配置，不能标为“从 env 搬过来”。不新增对应业务 env，直接落库。

| 分区 | 新增字段/操作 | 默认和范围 |
| --- | --- | --- |
| 平台信息 | 平台显示名称 | 默认沿用 Veges |
| 用户与角色 | 聚合权限保存、已有飞书用户授予超管、builtin 标记及授权来源 | 取消平台创建账号设计，普通新用户仅飞书自动注册；admin 内置例外；角色/启停/离职保留 |
| 组织管理 | 平台组织列表、新建、空数据检查、删除空组织 | 新建/删除仅超管平台页；组织管理员移除入口；任意业务关联数据阻止删除，不再解绑项目/测试空间或级联清空；保留账号及审计 |
| 管理入口 | 选择角色二级菜单增加超级管理员 | 按附图保留账户设置/更新日志/亮色模式/退出登录；组织管理员也在角色子菜单；无返回工作台按钮；未选择时隐藏平台页 |
| 凭据查看 | 已保存值和新输入值的显示/隐藏按钮 | 新增按需单字段 reveal 接口；默认查询仍脱敏；30 秒自动隐藏；不开放 APP 根密钥、账户密码哈希和内部旧签名材料 |
| 邮箱 | SMTP 启用、host、port、TLS 模式、用户名、密码、发件人名称/地址 | 整个邮件配置模块为新增；默认关闭，显式配置完整后启用 |
| 邮箱测试 | 测试收件地址、连接验证、发送测试邮件 | 收件地址仅为本次测试输入，不必持久化；发送不与保存绑定 |
| 全局 AI | 无新增参数 | 仅表中 8 个现有参数；取消独立启用开关和 7 个分类/并发新参数，内部保护继续使用现有常量 |
| 对象存储 | 无新增存储配置能力 | 历史存储/当前配置选择器为上版新增设计，当前未实现，本轮删除；默认开启，无关闭能力 |
| 飞书 | 回调展示/复制 | 事件回调和登录重定向地址由公网地址实时生成；公网地址保存或恢复后自动热更新，飞书开放平台仍需人工同步 |
| GitHub | 仓库地址、工作流文件、分支及逐项测试；独立启用开关 | 初值沿用原常量，目标可改；仅允许 github.com，历史任务绑定原目标，测试默认不运行工作流 |
| 包市场 | 校验规则 | 前端提交 YAML 并展示服务端校验结果，服务端保存时再次校验结构、路径、引用；错误阻止保存 |
| 集成测试 | AI/OSS/飞书/GitHub 连接测试及结果 | 新增管理操作，不是新的运行时 env；不自动触发 workflow 或发送消息 |
| 配置历史 | 版本、变更字段、操作者、恢复操作 | 服务端生成的元数据和操作，不是用户填写字段 |
| 热更新状态 | 已保存、服务加载中、已生效/异常、各进程版本 | 自动通知并加载、5 秒核对、每操作校验版本；不需重启或手动应用 |
| 数据安全 | key ID、加密覆盖/历史引用/巡检结果 | 只读状态，不开放 APP 密钥材料编辑 |

OAuth state 和附件 URL 签名密钥已经是现有 env 能力，不计入新增字段；前者按本期要求隐藏，后者仍可管理。当前使用单套 OSS 配置，不新增多存储表；删除“历史存储”页面区块并不删除历史附件数据。

## 5. 明确不迁入平台的启动/部署输入

用户排除的 7 项：`DATABASE_URL`、`DB_POOL_MAX`、`DB_POOL_CONNECTION_TIMEOUT_MS`、`DB_POOL_IDLE_TIMEOUT_MS`、`APP_ENCRYPTION_KEYS`、`APP_ENCRYPTION_ACTIVE_KEY_ID`、`PORT`。开发代理端口 `VEGES_API_PORT` 同属端口配置。

部署模板中的 `PG_HOST`、`PG_PORT`、`PG_USER`、`PG_PASSWORD`、`PG_ENDPOINT`、`PG_DATABASE` 属于数据库组装参数，同样排除。`NODE_ENV` 是进程运行模式，`DOTENV_CONFIG_PATH` 是启动文件选择器，不能作为热更新业务设置。镜像 `VEGES_IMAGE`、CI/Kubernetes 发布凭据和 CronJob 调度属于部署控制，不是应用已有业务 env，仍由部署平台管理；不因为加入平台设置而让应用负责自我发布。

## 6. 覆盖验收

1. 标准业务变量 34/34 去向明确：28 项可编辑/等价操作、1 项固定只读、2 项隐藏、3 项兼容迁移；旧别名 5/5 可导入；未实现项 2/2 在报告中可见。
2. 本机未填写的参数按该范围处理；不新增 AI 参数、不提供存储关闭能力。
3. 对每一项做保存、授权读取、脱敏、执行路径和运行时生效验收；既检查 API，也检查日报 worker/后台调度器。
4. 默认值以代码的实际有效配置为准。例如包市场时长代码回退为 1800 秒，而 .env.example 写 600 秒；显式配置必须按原值导入，不覆盖成统一模板默认值。
5. 新增 SMTP、GitHub 可变目标及规则校验独立测试；只读 GitHub 检查不能标为真实执行成功。
6. 事件回调和独立登录重定向均固定只读；附件签名密钥、完整规则及两种独立下载时长保留；隐藏字段不被覆盖。使用中存储位置变更需迁移，不承诺自动历史读取。管理员 env 不长期叠加授权，admin 永久保留。

本轮能力变化：取消上版平台创建账号设计，新增普通账号只能飞书自动注册的约束，admin 初始化例外；超管身份选择控制平台页可见性；热更新从仅新操作读取明确为通知自动刷新、轮询补偿和运行状态展示。继续保持回调只读、无历史存储、聚合权限保存。AI 五项限制及附件三项是已有参数，本机未填写时默认/回退已生效，页面展示不代表本轮新增后端能力。

附图融合调整：账号菜单复用附图结构，角色选项移入二级菜单；删除返回工作台；新增凭据明文显示。原“保存后永不回显”的设计被本轮明确要求替代，普通 DTO/日志/历史依旧不含凭据；仅授权的按需查看返回单个字段。附件签名若沿用了根密钥材料，先分离新独立签名密钥与不可查看的旧验证材料，不能通过此入口泄露 APP 密钥环。

新增组织生命周期要求不增加任何 env：复用已有组织表及新建能力，增加全平台治理查询/数据检查；新建入口搬到超管，组织删除权限收紧且行为从“解绑并清理”变为“非空拒绝”。唯一 owner 关系、组织基本字段和保留审计不阻止删除；其他成员及历史邀请、周报、模块、环境、资源/自定义配置等阻止，完整口径见主计划。配置历史恢复不回滚组织新建/删除。
