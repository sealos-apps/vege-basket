# 手动测试：按页面检查二次确认

状态：功能已实现；以下是用户人工验收清单，勾选框尚未代替用户验收。开发验证范围见文末。

这份是用户手测主清单。按页面走一遍，每一行列出的按钮都点过后再勾选。只需测试这些实际入口，不需要重复执行开发侧的全部异常用例。

## 每个按钮都按这三步检查

1. 第一次点击：出现确认，能看出操作对象和影响；数据不能立即消失或变成已完成。
2. 点“取消”：数据和原状态保留。再次点击同一操作，仍能正常弹出确认。
3. 点最终确认：成功后才删除或改变状态。完成、归档后的数据能从提示的位置找到。

已有“验收”“驳回理由”等表单，只需要该表单承担一次明确确认，不应连续弹两次。普通保存表单若会把业务对象改为结束状态，应在提交前明确确认。

使用一次性测试数据；项目、组织和测试空间删除放在最后。看不到某个管理入口时标记“无权限/未测”，换有该权限的测试账号，不能当作已通过。

## 一、项目和待办

- [ ] 01｜**项目篮子 → 项目搜索结果**：操作菜单“删除项目”；状态下拉“已结束”“归档”分别测一次。结束/归档后切到全部或对应状态，项目仍可打开。
- [ ] 02｜**项目 → 日记列表**：“删除日记”；已标记风险日记的“取消风险标记”。取消风险后原日记应保留。
- [ ] 03｜**项目 → 待办列表**：“删除待办”；勾选完成；提交验收；验收通过/不通过；驳回。用相应创建人、负责人、验收人账号测试可见入口；已有理由/验收表单只确认一次。
- [ ] 04｜**项目 → 待办详情**：详情内的验收和驳回入口也各测一次，避免只覆盖列表。若当前角色不显示某个按钮，记录其权限条件。
- [ ] 05｜**项目设置 → 模块**：“删除模块”。关联待办保留，模块归属清空。
- [ ] 06｜**项目设置 → 成员**：“移除成员”。已加入成员、待接受邀请各测一次；确认说明应区分移除和撤回邀请。
- [ ] 07｜**草稿箱**：“删除”“确认归档”“创建待办”分别测试。有项目和无项目时的两个删除入口都要覆盖；归档/创建后去所选项目找内容。
- [ ] 08｜**我的待办 → 点击事项 → 原业务详情**：进入详情完成后返回“我的待办”，检查未完成结果更新；选择“全部状态”可找回本人仍有关联的已完成事项。被驳回待办要去原项目按“已驳回”查看。

## 二、交付工作台

- [ ] 09｜**项目 → 交付 → 事件菜单/事件详情**：“删除事件”“标记已交付”。删除说明关联影响；交付完成后清除未交付筛选仍能找到事件。
- [ ] 10｜**交付 → 安装包时间线**：“删除安装包”。说明该安装包及其记录影响。
- [ ] 11｜**交付 → 记录操作**：“删除记录”有事件级和安装包级两处，两处都测试。
- [ ] 12｜**交付 → 交付反馈**：删除自己发表的反馈，应使用统一确认。
- [ ] 13｜**交付记录 → 关联待办**：勾选完成后保存，单个待办、两个待办各测一次；一次确认列出本次影响的待办。取消后不应提前保存关联关系或完成状态。

## 三、测试与 Bug

- [ ] 14｜**测试工作台 → 测试对象管理**：“删除测试对象”。确认说明对象下的用例、计划、Bug 等影响。
- [ ] 15｜**测试工作台 → 用例**：“删除测试用例”；目录树操作菜单“删除空目录”。删除源用例保留计划快照；空目录删除先确认，有用例或子目录时禁止删除。目录搜索、收缩、导入导出和移动不应重复弹出删除确认。上游已移除用例分类和“归档为基线”入口，无需测试旧入口。
- [ ] 16｜**测试工作台 → 测试计划详情**：“删除测试计划”；状态“已完成”“已终止”；未执行用例的“从计划移除”。四个动作分别测；从计划移除不能删除源用例。
- [ ] 17｜**测试工作台 → Bug 详情**：“删除 Bug”；状态“已关闭”“已驳回”；删除自己的普通评论。每个入口分别测试，其他人的评论或系统记录不能新增删除权限。
- [ ] 18｜**开发者 → Bug 工作台**：删除自己的普通评论；驳回 Bug。驳回继续使用原理由表单，不再追加一次通用确认；开发者不能因此获得关闭或删除他人 Bug 的权限。
- [ ] 19｜**测试空间管理**：“移除成员”“删除测试空间”。空间删除要输入准确名称，空/错误名称不能执行；成员移除不能删除成员创建的用例。

## 四、组织管理

- [ ] 20｜**组织管理 → 组织设置**：“删除组织”。输入准确名称才能执行；组织下项目和测试空间保留并解除组织归属。
- [ ] 21｜**组织管理 → 组织成员；项目 → 项目成员管理**：两处“移除成员”都测一次。一个移除组织成员，一个只移除项目成员，提示不能混淆。
- [ ] 22｜**组织管理 → 测试环境**：“删除测试环境”。新 Bug 不再可选，已有 Bug 的环境信息保留。
- [ ] 23｜**组织管理 → 项目管理**：项目管理表单保存名称、简介、标签及“已完成”“已归档”；组织 Owner/Admin 且具备组织管理员角色时，所有权转移选择成员并二次确认后立即生效，无需接收人确认；删除项目必须输入准确名称。里程碑状态快操作的“已达成”“已取消”各测一次。取消确认要保留编辑草稿、外层仍为原状态。
- [ ] 23a｜**组织管理 → 测试空间**：成员管理仅列出当前组织内具备测试空间资格的成员，选择未加入空间的成员后可直接加入；所有权转移选择同一范围成员，二次确认后立即生效、原所有者为可编辑成员，接收人通知中心不应出现新的转移申请。

## 五、其他入口

- [ ] 24｜**Veges AI → 对话历史**：“删除对话”。当前对话、非当前对话、正在生成的当前对话各测一次；取消不能提前停止生成。删除后已保存文档和已创建待办保留。
- [ ] 25｜**镜像同步 → 失败任务**：“清理失败任务”。只清理本地记录，不应删除远端产物。
- [ ] 26｜**账户设置 → 飞书绑定**：“解除绑定”。明确说明同时关闭每日推送；取消后绑定及订阅保留。
- [ ] 27｜**通知/邀请**：项目邀请“忽略”；测试空间邀请“拒绝”。都应先确认，取消后邀请仍待处理。

## 收尾只补测四件事

- [ ] 使用“待办完成”或“日记删除”连续点确认：只处理一次，等待期间按钮不能重复提交。
- [ ] 用开发者准备好的失败模拟点一次删除/完成：错误可见，弹窗保留，不能假装成功把数据隐藏。
- [ ] 手机窄屏打开一个确认：对象、说明、取消和确认按钮都能看见并操作。
- [ ] 改筛选、搜索、切页面、普通编辑、恢复未完成：不应被这次改动误加结束/删除确认。

无需用户自己模拟超时、权限变更、跨页并发或批量部分失败；开发侧已做模拟验证；真实环境的权限变更、级联删除和外部系统副作用仍需在独立验收环境验证。

## 开发验证范围

- `npm run build`、`npm run lint`、`npm test`、`git diff --check`；测试使用不可连接的本地数据库占位地址，仅满足纯函数模块加载，不连接或写入数据库。
- 新增回归覆盖丢失响应读回、明确权限/冲突拒绝、未知结果保留，以及批量部分失败后的剩余步骤重试和并发点击。
- 隔离浏览器使用实际共享组件和 AI 历史面板，模拟成功、失败、延迟、未知结果；检查取消焦点、等待锁定、名称确认、嵌套表单、下拉菜单、批量重试、上下文切换和手机窄屏。
- 未运行真实数据库、级联删除、飞书解绑/通知、AI 生成、GitHub Action、OSS 或部署测试。以上 28 个业务位置的完整成功链路仍由本清单进行人工验收。

网络超时或网关错误只表示结果未知：系统先在支持的入口读回核对，无法确认时禁止原弹窗及重新打开的同一操作重复提交。请刷新页面核对实际数据后再操作。批量已保存的步骤会保留，弹窗内重试只执行剩余步骤。
